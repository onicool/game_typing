# ゲーム体験設計書：段階0・段階1

作成：2026-10-08　状態：設計（未実装）

## 目的と範囲

現在のゲームを「入力練習の連続」から、**唱えた言葉が術になり、うまく唱えるほど物語が劇的に動くゲーム**へ変える。

本書が詳しく定めるのは次の二つ。

- **段階0**：手触りと締めくくりの改善
- **段階1**：ステージ1を一章として作り込む縦切り試作

段階2以降（全章の物語、章の解放、BGM、修行・日替わり・収集）は、8章に方針だけを置く。

数値は、特記がない限り試遊で調整する**仮値**。物語と人物の根拠は [世界観とキャラクター](../concept/WORLD_AND_CHARACTERS.md)、未確定事項の一覧は [制作予定](ROADMAP.md) を正とする。

## 1. 決定事項

2026-10-08にユーザーと合意した方針。

| 論点 | 決定 |
|---|---|
| 緊張感 | 道中は時間制限なし・反撃なし。ボス戦の反撃は「標準」では緩め。厳しい「挑戦」を別に選べる |
| 敗北 | 標準では敗北なし。結界が全部割れたら「祈り直し」（その場で結界が戻り、ランク上限が下がる）。挑戦では敗北あり |
| 姉弟の差 | エルナ＝長い言葉を正確に唱えると大技。トワ＝ミスなしの連続で連撃と結界回復 |

## 2. 現状の課題

実プレイとコードの監査で確認した問題。行番号は2026-10-08時点のもの。

1. **敵の反撃は演出だけ。** 防御か衝撃かは5.2秒周期の偶数・奇数で決まり、入力の出来とは関係がない（`src/fx/combat.ts:10`）。
2. **短く、最後の一撃が見えない。** 各土地は固定の5語（62〜83打鍵）。最終語の打鍵と同じ処理の中で `end()` が演出を止め、結果画面に置き換える（`src/main.ts:358-361`）。
3. **スコアが残らず、別綴りで差が出る。** スコアは結果画面にも保存にも残らない。加点が打鍵単位なので、`shi` のような長い別綴りが有利になる（`src/main.ts:355`）。
4. **成果が残らない。** 実績名は全土地で同じ。クリア状態を保存しない。章バーは、選択中の土地を含めてそれ以前を点灯し、達成とは関係がない（`src/main.ts:124`）。
5. **旅が途切れる。** 「次の場所へ」は地図に戻るだけ（`src/main.ts:292`）。
6. **選択と物語が遊びに出ない。** 姉弟の差は台詞だけ。土地ごとの目的・相手・結果が画面に出ない（`src/game/journey.ts:4`）。
7. **結界の表示は使えない状態で残っている。** 翼表示のCSS（`.av-wings`、`src/style.css:18`）は残っているが、戦闘HUDのHTMLにはない。

## 3. 体験の目標

| 項目 | 目標（仮値） |
|---|---|
| 一章の長さ（標準） | 中級者（約3かな／秒）で約2〜2.5分、初心者（約1.5かな／秒）で約3.5〜4分。内訳は5.3の試算 |
| 一章に必ず用意する機会 | 予兆を見て唱え切る／弾き返す／姉弟の大技を出す／撃破の決着／成果が地図に残る。最初の反撃はボス戦開始から3秒で必ず起こす。大技は条件を満たしたときに出る |
| 初心者 | 標準では必ずクリアでき、失敗しても入力が止まらない |
| 上級者 | 挑戦では反撃の猶予が短く、Sランク・星3に挑む理由がある |
| 試遊で確かめること | 「何のために打ったか」を説明できる／「もう一度」か「次の章」を自分から選ぶ |

## 4. 段階0：手触りと締め（1〜3日）

既存の5語の道中を保ったまま、全7土地に効く改善を入れる。

### 4.1 最終語の決着演出

**時刻の扱い**

- 最終語が完成すると、その入力処理の中で `Round` が `endT` を確定する（`src/game/round.ts:292`）。
- 結果に使う所要時間は、`endT` で固定された `round.elapsedMs()` とする。終了日時 `endedAt`（`Date.now()`）も、結果表示時ではなく**終端の確定時**に取る。演出の時間はどちらにも含めない。

**演出の進め方**

- `main.ts` は直ちに `end()` を呼ばず、`finale` 状態を挟む。
- ゲーム内時計は止まっているため、演出は `performance.now() - finaleStartedAt` で進める。
- `finale` の対象は、開始時の `Round` の参照で識別する。別の `Round` が始まったら、古い `finale` は何もしない。
- 現在のフレーム処理は、`round.finished` なら直ちに `end()` を呼ぶ（`src/main.ts:371`）。`finale` 中はこれを行わず、演出の終了時に `end()` を呼ぶ。
- `CombatScene.hit()` は命中表示を次の `tick` まで保留する（`src/fx/combat.ts:136`）。そのため、ゲーム内時計と独立して描画する `CombatScene.finale(ms)` を追加する。

| 場面 | 演出 |
|---|---|
| 演出あり | 600ms：ヒットストップ（約80msの静止）→ 白い閃光 → 封印の破砕または機体への強打 → 結果 |
| 動きを減らす設定・低負荷 | 300ms：静止した成功表示 |

**入力とスキップ**

- `finale` 中のゲーム入力は `Round` に渡さない。
- Escは、IME・修飾キーの除外判定の後、かつ通常の `finished` 判定の前に処理し、即座に結果へ進む。
- 戦闘画面内のクリックでも結果へ進む。ヘッダーの操作は、プレイ中と同じく無効のままにする。
- 演出中にページが非表示になったら、復帰時に結果を表示する。

**結果画面の誤操作防止**

結果を表示してから500msは、結果画面のボタンへのキー操作とクリックを受け付けない。保存の二重実行は、既存の `endedRound` 判定で防ぐ。

### 4.2 スコア・ランク（新規 `src/game/score.ts`、純粋関数）

**スコア**は打鍵数ではなく、**確定したかなの数**で数える。

- 画面に表示するコンボは、今までどおり打鍵の連続数（`round.chain`）とする。
- 加点に使う倍率は、別に持つ「**かなコンボ**」（ミスなしで連続して確定したかなの数）で決める。ミスすると0に戻る。
- 1回の打鍵で確定したかなが複数ある場合（拗音・促音など）は、1文字ずつ順にかなコンボを進め、その時点の倍率をかけて加点する。こうすると、`shi`／`si` や、拗音をまとめて打つか分けて打つかで得点が変わらない。
- 確定したかなの増分は、打鍵前後の `round.session.kanaDone` の差から求める（語の完成時は残りの分）。

| 加点 | 値 |
|---|---|
| かな1文字の確定 | 10 × 倍率 |
| 語の完成 | +100 |
| ミスなしの語 | さらに +50 |
| 段階1のみ：弾き返し／大技／撃破 | +200 ／ +100 ／ +1000 |

倍率は、かなコンボ0〜9で×1.0、10〜29で×1.2、30〜49で×1.5、50以上で×2.0。

**ランク**は、勝利または完了した結果にだけ付ける。途中終了・敗北・語数上限による終了には、ランクも星も付けない。速度はランクに使わず、自己ベスト時間で別に示す。

段階0（道中・S/A/Bの3段階）：上から判定し、最初に当てはまるもの。

| ランク | 条件 |
|---|---|
| S | 正確率98%以上、かつミスなしの語が80%以上 |
| A | 正確率95%以上 |
| B | それ以外の完了 |

段階1（章）：上から順に判定する。

| 順 | 条件 | ランク |
|---|---|---|
| 1 | 祈り直しが2回以上 | C |
| 2 | 祈り直しが1回 | B |
| 3 | 正確率97%以上、解決した反撃が3回以上、弾き返し率80%以上 | S |
| 4 | 正確率94%以上、弾き返し率60%以上（解決した反撃が0回なら正確率のみで判定） | A |
| 5 | それ以外の撃破 | B |

- 「解決した反撃」とは、弾き返しかひびで決着した反撃を指す。撃破で取り消された反撃は、弾き返し率の分母に含めない。
- 結果画面に表示するもの：スコア、ランク、所要時間、自己ベストの更新。既存の速度・正確率・最大コンボも残す。

### 4.3 コンボの段階演出

- 表示コンボが10・30・50に達すると段階が上がる。各段階で、入力済みローマ字の光量、パネル上縁の金線、羽の粒子数（既存の上限内）を一段ずつ強める。
- 打鍵音の音程を段階ごとに半音上げる。`Audio.key(stage, critical, comboTier = 0)` のように引数を追加し、既存の呼び出しはそのまま動くようにする。既存の `stage` は速度・リズムの段階なので、別の値として扱う。
- コンボ10以上でミスしたら「コンボ途切れ」を0.8秒表示し、短い下降音を鳴らす。
- 動きを減らす設定では、光と粒子を変えず、数字と短いテキストだけにする。

### 4.4 旅を止めない導線

- 第1〜6土地を完了したときは、「次の場所へ」を主ボタンにする。押すと地図を経由せず、次の土地をすぐ始める。「もう一度」は副ボタンにする。
- 第7土地を完了したとき、および途中終了のときは、「旅の地図」を主ボタンにする。
- 誤操作の防止は4.1の500ms規則で行う。

### 4.5 土地ごとの一言

- `Place` に `intro`（開始時、20〜35字）と `outro`（完了時、20〜35字）を追加する。開始時は台詞窓に、完了時は結果画面の見出しの下に出す。
- 成功の台詞は毎語では繰り返さず、最初の突破・中盤・完了で変える。
- 段階0で書くのはステージ1・2の文面だけ。他の土地は既存の台詞のままとし、世界観資料と整合を取ってから書く。

### 4.6 旅の成果の保存（新規 `src/game/progress.ts`）

設定ストアのキー `angel.progress` に保存する。値の検証関数を用意し、`settings.get()` で検証関数を登録してから `set()` する（既存の仕様、`src/storage/settings.ts:53`）。

```ts
interface PlaceRecord {
  cleared: boolean;
  bestScore: number;           // scope が 'chapter' または 'route' の記録だけで更新する
  bestRank: 'S' | 'A' | 'B' | 'C' | null;
  bestTimeMs: number | null;   // 同上
  stars: [boolean, boolean, boolean];
}
interface PlaceProgress {
  routeVersion: number;        // 出題・ルールの版。段階0の道中=1、段階1のステージ1章=2
  current: PlaceRecord;        // 現在の版の成果
  legacy?: PlaceRecord;        // 版が上がる前の成果。表示のみに使い、クリア扱いにしない
}
interface Progress { version: 1; places: Record<string, PlaceProgress>; } // キーは Place.key
```

**地図の表示**

- 章バーは `current.cleared` に従って点灯させる。
- 地図のカードには、クリア印、星、最高ランクを表示する。`legacy` だけがある土地には「旧道中クリア」と小さく表示する。

**章を鍵で閉じない**

段階0では、全土地を選べる今の状態を保つ。まだクリアしていない最初の土地に「おすすめ」を付ける。鍵による解放は、章が実際に完成する段階2で入れる。

**版が上がったとき**

コードの `routeVersion` が保存値より新しければ、保存値の `current` を `legacy` に移し、`current` を空にする。旧版の成果は消さないが、新しい章のクリアや「おすすめ」の判定には使わない。

**複数タブでの保存**

保存の直前に保存域の最新値を読み直し、土地ごとに統合する。統合するのは、**同じ `routeVersion` どうしの `current` だけ**とする。

- 保存域の値の版がこのタブより古い場合は、先に上の「版が上がったとき」の移行を行ってから統合する。
- 保存域の値の版がこのタブより新しい場合（古いコードのタブ）は、保存域の `current` を変更しない。このタブの成果は `legacy` 側にだけ統合する。
- 旧版の成果が、新しい版のクリア・星に混ざることはない。

同じ版どうしの統合規則は次のとおり。

| 項目 | 統合規則 |
|---|---|
| `cleared`・星 | どちらかが真なら真 |
| `bestScore`・`bestRank` | 良い方を残す |
| `bestTimeMs` | 同じ `routeVersion` の中で短い方を残す |

設定ストアには、最新値を読み直す手段を追加する。

**保存の失敗**

- 成果の保存と打鍵記録の保存（IndexedDB）は互いに独立して行い、片方の失敗で他方を取り消さない。
- 成果の保存に失敗したら、結果画面に「旅の成果はこのページでのみ保持」と、打鍵記録の保存状態とは別に表示する。

**段階0の星**

★1 完了、★2 正確率95%以上、★3 ミスなしの語が5語中4語以上。いずれも完了した結果でのみ得られる。

### 4.7 記録の追加項目

`saveSession` に渡すメタ情報に、次の任意項目を加える。

`character`、`score`、`rank`、`routeVersion`、`elapsedMs`、`scope`（`'route'` / `'chapter'` / `'boss'`）、`seed`

段階1ではさらに次を加える。

- `difficulty`
- `outcome`：`cleared` / `lost` / `quit`
- `endReason`：`finish` / `word-limit` / `defeat` / `user`
- `parentSession`：ボスからの再挑戦が、どの記録の続きかを示す

型は、`src/stats/store.ts` の `SessionMeta`（3行目）、`saveSession` の引数（76行目）、読み込み関数の戻り値（220行目付近）の3か所を、共通の型にまとめて更新する。既存の記録はこれらを持たないため、どれも省略可能とする。`mode` の値と、60秒計測の自己ベスト判定は変更しない。

## 5. 段階1：ステージ1を一章として完成させる（1〜2週間）

### 5.1 章の流れ

導入会話 → 道中（8語・反撃なし） → ボス登場（時計停止） → ボス戦（HP・反撃） → 決着演出 → 結果 → 後日談 → 地図

**導入**

- セラと主人公の会話、4〜6発言。
- 初回だけ、IMEをオフにすることと「ミスはそのまま打ち直す」ことを、セラの言葉で案内する。
- 操作：Space/Enterで送る。Escで全部飛ばす。

**道中**

- 20語の候補から、シード付きで8語を抽選する。短い語から始め、後半に拗音・促音・「ん」を含む語を置く。
- 既存の封印突破の演出を使う。
- 時間制限はない。

**ボス登場**

- セラが門の守護機を起動する（2発言）。守護機は、既存の輪腕衛機（仮素材）を使う。
- この間は `Round` を内部で一時停止する（5.2）。
- 約2秒で自動的に進み、キーを押せば飛ばせる。

**ボス戦**：5.3〜5.5で定める。

**決着**：4.1の演出を、撃破専用に900msへ延長する。

**後日談**

- 2〜3発言。セラが落ちた羽飾りを拾って渡す（世界観資料の案）。
- 操作：Space/Enterで送る。

**セラと守護機の扱い**

世界観資料では、最後に主人公を止めるのは親しい上級天使（採用方針）で、ステージ1のボスはセラ（構成案）。縦切り試作では、セラが主人公を止める筋はそのまま保つ。戦う相手は、仮素材の守護機とする（試作上の判断）。セラ本人と戦うかどうかは段階2で決める。

**会話の置き場所と時計**

- 会話の文面は本書では決めない。`src/content/chapters.ts`（新規）に置き、世界観資料の台詞候補から起こす。
- 会話の表示中は `Round` の時計を進めない。道中の最初の打鍵で時計が始まる（既存の仕様）。

### 5.2 Round との関係

**一章を一つの Round にまとめる**

- 一章を一つの `Round`（`mode: 'journey'`）で扱う。
- 出題源は新しい `ChapterSource` とする。道中の8語を出した後、ボス用の語を順に出し続ける。
- 先読みの2語には、道中の終盤からボス用の語が出る。予告の順番は、確定した後で入れ替えない（既存の仕様）。

**道中からボス戦への切り替え**

- 道中の8語目が完成したら、`round.pause(t)` で時計を止め、ボス登場を表示する。
- 登場が終わったら `round.resume(t)` で再開し、`battle.startBoss(gameMs)` を呼ぶ。
- この一時停止は、停止ダイアログを出さない内部の停止とする。再開直後の打鍵が速度分析から外れる点は、既存の仕様のまま受け入れる。

**終了の扱い**

- 実際の終了は、`Battle` が撃破または敗北を返したときに、`round.finish(t)` で行う。`finish` が効くのは、開始済みの journey と passage だけ（`src/game/round.ts:184`）。
- `wordLimit` は安全のための上限として60にする。`Round` はこの上限に達すると、自動で `endT` を確定する（`src/game/round.ts:292`）。
- そのため `main.ts` は、語が完成するたびに**完成を先に `Battle` へ渡し、その後で `round.finished` を見る**。上限の語で撃破した場合も勝利になる。
- 勝敗が決まらないまま上限に達した場合は、`outcome: 'quit'`、`endReason: 'word-limit'` とし、クリア・星・最高記録を更新しない。
- 結果画面の完了判定は、`wordsDone === wordLimit` ではなく、`Battle` の勝敗で行う。

**ボスからの再挑戦**（挑戦で敗北した後）

- 導入と道中を飛ばした、新しい `Round` として始める（`scope: 'boss'`）。
- 元の敗北の記録は変更しない。再挑戦は別の記録として保存し、`parentSession` で元の記録とつなぐ。
- 直近の速度の初期値は、元の記録の最後の測定値を引き継ぐ。
- 再挑戦で撃破すれば、`cleared` と星は更新する。最高スコアと最高時間は、章を通しで遊んだ記録（`scope: 'chapter'`）だけで比べる。

### 5.3 戦闘ルール（新規 `src/game/battle.ts`、純粋モジュール）

戦闘の状態とルールは、`Battle` だけが持つ。`CombatScene`（描画）と `Round`（入力判定）は、HPも勝敗も持たない。これは、既存の「演出は入力やダメージを持たない」方針を引き継ぐもの。

```ts
type Difficulty = 'standard' | 'challenge';
interface BattleConfig {
  character: Character; difficulty: Difficulty; bossHp: number; seed: number;
  initialKanaPerSec?: number;     // ボスからの再挑戦で、前回の測定値を引き継ぐ
}
interface WordView { index: number; kana: number }   // index は出題の通し番号
interface InputView { current: WordView; remainingKana: number; previews: [WordView, WordView] }
type BattleEvent =
  | { type: 'damage'; amount: number; special: 'judgment' | 'ring' | null }
  | { type: 'windup'; marked: number[]; dueAt: number }   // 防御の言葉の通し番号（1語または2語）
  | { type: 'parry' } | { type: 'crack'; cracks: number } | { type: 'restore'; cracks: number }
  | { type: 'prayer-reset' } | { type: 'phase2' } | { type: 'victory' } | { type: 'defeat' };

class Battle {
  constructor(config: BattleConfig);
  routeWordDone(w: { kana: number; durationMs: number }): void;   // 道中で速度だけを測る
  startBoss(gameMs: number): void;
  wordDone(w: { index: number; kana: number; clean: boolean; gameMs: number }, view: InputView): BattleEvent[];
  tick(gameMs: number, view: InputView): BattleEvent[];
  snapshot(): BattleSnapshot;   // hp, cracks, attack, ringStreak, phase, stats
}
```

**時刻と速度**

- 時刻はすべて、一時停止を除いた**ゲーム内時刻** `round.elapsedMs(now)` を使う。一時停止中は進まず、最初の打鍵までは0なので、反撃は起きない。
- 語の所要時間は、前の語の完成（またはボス戦の開始）から、その語の完成までの、ゲーム内時刻の差で測る。
- 直近の速度は、直近3語の「合計かな数 ÷ 合計所要秒数」とする。測定値がない、または所要時間が0のときは、`initialKanaPerSec`、それもなければ2.0かな／秒を使う。
- 乱数は `seed` から作る。同じシードと同じ入力列なら、同じ結果になる。

**ダメージ**（仮値。ボスのHPは240）

| 条件 | ダメージ |
|---|---|
| 語の完成 | かな数 × 1.0 |
| ミスなしの語 | × 1.25 |
| エルナ「裁きの一撃」：8かな以上のミスなしの語 | × 1.8（ミスなしの倍率の代わり） |
| トワ「光輪連撃」：ミスなしの語を3語連続 | その語のダメージに +10。ひびがあれば結界を1回復。連続数は0に戻る |
| 弾き返し（5.4） | +8 |

- 速度による倍率は掛けない。速く打てる人は攻撃の回数が増えるので、そのぶん早く終わる。
- 能力の判定には、かな数と、語単位の正確さだけを使う。別綴りの打鍵数では稼げないようにする。

**ボス戦の長さの試算**（ボス用の語は8〜14かな、平均約11かな）

| 想定 | かなあたりの実効ダメージ | 弾き返しの加算 | 必要なかな | 入力時間 |
|---|---|---|---|---|
| 中級者 3かな／秒、正確 | 約1.3 | 約6回、+48 | 約148 | 約50秒 |
| 初心者 1.5かな／秒、ミス多め | 約1.1 | 約4回、+32 | 約190 | 約125秒 |
| 上級者 6かな／秒、正確 | 約1.4 | 約3回、+24 | 約155 | 約26秒 |

これに道中（中級者で約25〜40秒、初心者で約45〜60秒）と会話（導入・ボス登場・後日談の合計で約40〜60秒）を加えると、一章は中級者で約2〜2.5分（115〜150秒）、初心者で約3.5〜4分（210〜245秒）になる（3章の目標）。

### 5.4 反撃と「防御の言葉」

**1. 予兆**

- ボス戦の開始から3秒後に、最初の予兆を出す。
- 予兆が出た時点で、先読みの次の1語（後半戦の「2語防御」なら次の2語）を防御の言葉として固定する。
- 防御の言葉は金色の枠で光らせ、期限までの残り時間を枠の周りの細い円弧で示す。
- 進行中の反撃の内容は、後半戦に移っても変えない。

**2. 期限**

```
dueInMs = 1000 × (今の語の残りかな数 + 防御の言葉のかな数の合計) ÷ 直近の速度（かな／秒） × 余裕係数
```

- 余裕係数：標準1.6、挑戦1.15。後半戦では、それぞれ0.15下げる。
- dueInMs の範囲（防御の言葉が n 語のとき）：

  | 難易度 | 下限 | 上限 |
  |---|---|---|
  | 標準 | 5秒 | 20秒 × n |
  | 挑戦 | 3.5秒 | 14秒 × n |

- ただし上限は、余裕係数を除いた必要入力時間の1.1倍を下回らない。
- 例：標準・後半戦・2語防御、残り14かな＋14かな×2＝42かな、1.5かな／秒の場合。必要入力時間は28秒、係数込みで約40.6秒、上限は40秒なので、期限は40秒。

**3. 判定**

- 期限の時刻までに、防御の言葉をすべて完成させれば弾き返し（防御の演出と、反撃のダメージ）。期限の時刻ちょうどの完成も成功とする。
- 間に合わなければ、結界にひびが1つ入る（衝撃の演出）。
- 語の中のミスの有無は問わない。

**4. 同時に起きたときの処理順**

1. 打鍵があったら、まずその打鍵時刻で `tick` を呼ぶ。期限がその時刻より**前**に切れていた反撃は、ひびとして先に処理する。
2. 次に `wordDone` を処理する。順番は、弾き返し → ダメージ・回復 → 撃破の判定。
3. 撃破した時点で残っていた反撃は取り消し、弾き返し率の分母に含めない。
4. フレーム処理の `tick` は、上記に当てはまらない期限切れだけを処理する。

**5. 間隔**

- 同時に出る反撃は一つだけ。
- 決着から次の予兆までは、標準5秒、挑戦3秒（後半戦では、それぞれ1秒短くする）。
- 防御の言葉が章の最後の語になることはない。ボス用の語は撃破まで出し続けるため。

**6. 後半戦**（HPが50%以下）

- 台詞を一つ表示する。入力は止めない。
- 反撃の3回に1回を、2語防御にする。

**結界**

ひびは最大3つ。結界の表示は、HUDの左上に新しく作る。残っている `.av-wings` のCSSは、この表示に合わせて整理する。

- **標準**で3つ目のひびが入ったら「祈り直し」。その反撃はそこで決着とし、結界を全回復する。ボスのHPはそのまま残す。ランク上限が下がる（4.2）。入力は止めず、次の予兆までは通常の間隔を置く。
- **挑戦**で3つ目のひびが入ったら敗北。`round.finish(t)` で終了し、結果は「敗北」になる。主ボタンは「ボスから再挑戦」。

### 5.5 描画・音の変更

**描画**

- `CombatScene.tick(elapsed, started)` の固定周期をやめ、`render(snapshot, gameMs)` に置き換える。予兆・接近・防御／衝撃の切り替えは、`Battle` の反撃状態から決める。
- 予兆の軌道、600msの接触表示、強打の表示は流用する。
- 今の `combatPhase()` の周期関数は、道中の背景演出か、テスト用としてだけ残す。
- HUDに追加するもの：ボスのHPバー（上部中央、章の表示の下）、結界のひび（左上、新設）、トワの連続数（小さな光輪3つ）。

**大技の演出**

| 天使 | 演出 |
|---|---|
| エルナ | 縦に長い光の筆跡がボスを貫く（約500ms） |
| トワ | 光輪3つの連撃（約450ms） |

どちらも、動きを減らす設定では静止画と文字に置き換える。

**音**：予兆・弾き返し・ひび・大技・撃破の効果音を `Audio` に加える。BGMは段階2で扱う。

### 5.6 難易度の選択

- 地図の「この場所へ」の隣に、「標準／挑戦」の切り替えを置く。設定キーは `angel.difficulty`、初期値は標準。
- 挑戦は最初から選べる。地図には「標準で一度クリアしたら挑戦がおすすめ」と表示する。
- 成果は、難易度ごとに分けては保存しない。結果画面と記録に難易度を表示する。
- 星3は標準でも取れる条件にする（5.7）。

### 5.7 結果画面と星（ステージ1）

**表示するもの**

勝敗、ランク、スコア、所要時間、弾き返し（成功数／解決した反撃の数）、大技の回数、祈り直しの回数、星。

**星**（撃破したときだけ得られる）

| 星 | 条件 |
|---|---|
| ★1 | 撃破 |
| ★2 | 正確率95%以上 |
| ★3 | 解決した反撃が1回以上あり、ひびが0回 |

**ボタンなど**

- 主ボタン：勝利なら「後日談へ」→「次の場所へ」。挑戦での敗北なら「ボスから再挑戦」。
- 既存の弱点フィードバック（遅い遷移、ミスの多いキー）は残す。段階3で、修行への導線に変える。

## 7. 検証

### 単体テスト

**score**

- かなを基準に加点する。`shi`／`si` で同じ得点になる。拗音・促音をまとめて打っても分けて打っても同じ得点になる。
- 倍率の境界（9→10など）を、1文字ずつ正しく適用する。
- ランクの判定順を守る。勝利・完了していない結果にはランクが付かない。

**progress**

- 検証関数が不正な値を拒否する。
- 版が上がったら `legacy` に移す。
- 統合規則が正しく働く。
- `routeVersion` が違う記録と時間を比べない。

**battle**

- 同じゲーム内時刻でも、防御の言葉の完成が期限以前なら弾き返し、期限後ならひびになる。
- 期限ちょうどの完成は成功する。
- 一時停止をはさんでも結果が変わらない。
- 2語防御は、2語とも完成したときだけ成功する。
- 処理順：撃破と期限が同時なら撃破を優先し、残った反撃を取り消す。
- 祈り直しは一度だけ起き、直後のフレームで再びひびが入らない。挑戦では敗北になる。
- 裁きの一撃の条件（7かなと8かなの境界、ミスの有無）。光輪連撃の連続数と回復。
- 期限の範囲（下限、上限、必要入力時間×1.1の下限）。速度の測定値がないときの代わりの値。
- 同じシードと同じ入力列で、同じ結果になる。

**ChapterSource と Round の接続**

- 同じシードなら同じ8語が出る。章の中で語が重複しない。道中の後にボス用の語が続く。
- 上限の語で撃破したら勝利になる。勝敗が決まらないまま上限に達したら `word-limit` になる。

### ブラウザ検証

- `angel_integration_check.py`：会話送り、8語の道中、長さが変わるボス戦、次の章の直接開始に対応させる。IME・フォーカスの分離、保存の障害と遅延完了、長文、60秒計測の既存の検証は残す。
- `angel_finish_check.py`：
  - 決着演出の後に結果が出る。
  - 終了時刻は演出の前に確定している。
  - 保存は1回だけ行われる。
  - 演出中にEscを押すと、すぐ結果に進む。
  - 結果表示から500msの間は、ボタンの誤操作が起きない。
  - 「次の場所へ」で、次の土地がすぐ始まる。
- `stage1_combat_check.py`：固定周期の検証を、HPの減少・弾き返し・ひび・祈り直し・撃破の流れの検証に置き換える。
- `stage1_frame_cost_check.py`：大技と撃破の演出を実際に起こす操作を加える。合格の目安は、JSのフレーム処理時間のp95が2ms以下（仮値）。既存の記録はp95 約0.4〜0.6ms（`docs/review/zip-integration-edd518b.md`）。

### 試遊

対象は、初心者2人以上と経験者2人以上。

- **記録すること**：章の所要時間、祈り直しの回数、弾き返し率、「もう一度」と「次へ」のどちらを選んだか。
- **終了後に聞くこと**：「何のために打ったか」「一番気持ちよかった瞬間」「焦りすぎた場面」。
